# pnpm Workspace Import Findings

## Problem

Running `pnpm import` failed because pnpm attempted to download `@earendil-works/pi-coding-agent@^0.7.1` from the npm registry. That version is not published; the registry currently contains versions beginning at `0.74.0`.

pnpm also warned that it does not use the `workspaces` field in `package.json` and requires a `pnpm-workspace.yaml` file.

## Root Cause

`@earendil-works/pi-coding-agent@0.7.1` and the other `@earendil-works/pi-*` packages exist locally under `packages/` at version `0.7.1`. Without a pnpm workspace manifest, pnpm treated them as registry dependencies instead of local workspace packages.

After adding the workspace package paths, pnpm recognized the packages but still attempted to resolve matching dependencies from the registry. This pnpm configuration required `linkWorkspacePackages: true` to link dependencies whose semver ranges match local workspace versions.

The dependency versions did not need to be changed. Updating them to the latest registry release would have been incorrect and would also have conflicted with the repository's seven-day dependency release-age policy for the newest releases.

## Work Completed

Created `pnpm-workspace.yaml` with:

- All workspace paths from the root `package.json`.
- `linkWorkspacePackages: true` so local `@earendil-works/pi-*` packages resolve through workspace links.
- The existing `blockExoticSubdeps: false` pnpm setting.
- An `allowBuilds` list generated by `pnpm approve-builds --all` for the dependencies whose install scripts are required.

Reran `pnpm import`, which completed successfully and generated `pnpm-lock.yaml`. The lockfile records the local packages as workspace links, including:

```yaml
'@earendil-works/pi-coding-agent':
  specifier: ^0.7.1
  version: link:packages/coding-agent
```

Installed dependencies and resolved strict pnpm dependency isolation failures by declaring packages where they are imported:

- Added `@smithy/node-http-handler` and `@smithy/types` to `packages/ai` runtime dependencies for the Bedrock provider.
- Added `esbuild` to root development dependencies for `scripts/check-browser-smoke.mjs`.

## Validation

`pnpm import` exited successfully with code `0`. The full `pnpm run check` command then passed, including Biome, TypeScript, installer rendering, and the browser smoke check.

Dependency installation reported two deprecated transitive dependencies:

- `node-domexception@1.0.0`
- `prebuild-install@7.1.3`

No source files were modified as part of the pnpm compatibility work. The separate `auth-flows.ts` change was committed independently. The pre-existing untracked `pnpm-workspace.example.yaml` was left untouched.
